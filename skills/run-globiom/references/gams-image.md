# Own GAMS version

Use this path when the user does not want `GAMS52_5__R4_6`, or when the restart checkpoint (`Model/t/a4_r1.g00`) was generated by a GAMS version other than 52.5.

## Checkpoint version matching

GAMS restart workfiles (`.g00`) are binary files that can only be opened by the same or compatible GAMS release. Opening a newer checkpoint in an older GAMS version (e.g. loading a GAMS 53.3 checkpoint in GAMS 52.5) fails with:
```text
*** Gams Exit Msg = New Workfile (Exit code 5)
```

To determine the exact GAMS version that created a checkpoint, inspect the first line of `Model/t/a4_r1.g00`:
- `WEX533-533` -> Windows 64-bit GAMS 53.3
- `LEX525-525` -> Linux 64-bit GAMS 52.5
- `WEX480-480` -> Windows 64-bit GAMS 48.0

In PowerShell:
```powershell
(Get-Content -Path "Model/t/a4_r1.g00" -Encoding Byte -TotalCount 100 | ForEach-Object { [char]$_ }) -join ""
```
Always match the container's GAMS version to this checkpoint version.

## Requirements

Ask for or verify:
- the GAMS version, such as `53.3.0`
- the license file name (e.g. `gamslice.txt`)

Put the license file in the model root. That directory is `job_folder`. Do not exclude it. Do not print it.

The platform copies the filtered model root to `/code`. The command must use `license=/code/<filename>` and `//extra_parameters=license=/code/<filename>`. Check that this path matches the file name in the model root before dispatch. `execute_abort` children do not inherit `license=`. They open the image `gamslice.txt`. The job user cannot replace that file.

## Dockerfile

Write `Dockerfile` in the model root. Set `docker_filename="Dockerfile"`. Do not set `base_stack`.

Build as root. Run the job as `65534:65534`. Install GAMS before the `USER` line. Copy the model after the install, or the copy can overwrite `/opt/gams`.

```dockerfile
FROM rocker/r2u:22.04

ARG GAMS_VERSION=53.3.0
ENV GAMS_VERSION_SHORT=53.3 \
    GAMS_BIT_ARC=x64_64
ENV GAMS_PATH=/opt/gams/gams${GAMS_VERSION_SHORT}_linux_${GAMS_BIT_ARC}_sfx
ENV PATH="${PATH}:${GAMS_PATH}" \
    LD_LIBRARY_PATH="${GAMS_PATH}"

RUN apt-get update \
    && apt-get install -y --no-install-recommends curl ca-certificates \
    && rm -rf /var/lib/apt/lists/* \
    && mkdir -p /opt/gams \
    && cd /opt/gams \
    && curl -fsSL \
        "https://d37drm4t2jghv5.cloudfront.net/distributions/${GAMS_VERSION}/linux/linux_${GAMS_BIT_ARC}_sfx.exe" \
        -o gams.exe \
    && chmod +x gams.exe \
    && ./gams.exe \
    && rm gams.exe \
    && chmod -R 755 /opt/gams \
    && ln -s ${GAMS_PATH}/gams /usr/local/bin/gams \
    && ln -s ${GAMS_PATH}/gdxmerge /usr/local/bin/gdxmerge

WORKDIR /code
COPY --chown=65534:65534 . /code
USER 65534:65534
```

Replace `GAMS_VERSION` and `GAMS_VERSION_SHORT` with the target version (e.g., `53.3.0` and `53.3`).

### Key details in this Dockerfile:
1. `rocker/r2u:22.04` (or `debian:bookworm-slim`) provides a clean Linux environment with R and system libraries.
2. Installing `curl` and `ca-certificates` is required so `curl` can fetch the SFX installer from CloudFront.
3. `chmod -R 755 /opt/gams` ensures non-root user `65534:65534` can read and execute all GAMS utilities and shared libraries.
4. Symlinks in `/usr/local/bin` (`gams`, `gdxmerge`) ensure commands are available across all subshells and PATH variations.
5. `USER 65534:65534` must stay after `COPY`. The job writes under `/code`, which that user owns. Do not run the job as root.
